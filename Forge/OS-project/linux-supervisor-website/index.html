IPC Anonymous Pipe Heartbeat Telemetry

Child processes inherit pipe fd 3 (SUPERVISOR_HB_FD) and transmit periodic pulses

Watchdog Active

Every worker configured with heartbeat_timeout writes 'H' to pipe fd 3 every 2 seconds. The supervisor event loop reads from the pipe non-blockingly via select(). If a worker hangs or fails to beat within its timeout window, the supervisor watchdog flags it as UNHEALTHY and triggers automated recovery.

Process signals enabled:

Clicking Stop sends SIGTERM to the child's process group. Kill sends SIGKILL. Pause suspends execution via SIGSTOP, and Resume wakes it up via SIGCONT. Failed services automatically restart according to the backoff schedule.

Execution & Telemetry Pipeline

How requests flow from your click to the Linux kernel

1
User Action in Browser

User clicks "Restart" on a service. The browser issues a POST to /api/action with {"action":"restart", "service":"flaky"}.

Frontend
2
Embedded C HTTP Server Processing

The C supervisor's select() loop unblocks on the listening socket, reads the request, parses the JSON payload, and calls restart_service().

C Engine
3
POSIX Process Control & Signal Dispatch

The C supervisor invokes stop_service() (sending SIGTERM to the child PGID), reaps it via waitpid(), and immediately calls fork() and execvp() to relaunch.

Linux Kernel
4
Live Telemetry & Log Output

All events are appended to logs/supervisor.log using unbuffered write(). The UI polls /api/status and updates the table and logs instantly.
